# Expo Go Local Preview and Continuous Use

This guide explains how to run the BD Admission app in Expo Go from the local project checkout, keep the preview available while working, reconnect after a restart, and stop the server safely.

The Metro/Expo development server runs from this repository on the device that hosts the checkout. On the current Android/NetHunter Rootless setup, use Expo's **tunnel** transport for Expo Go connectivity: LAN mode previously advertised a loopback-only address, which is not usable by another app/device as a LAN address. Tunnel mode is still a local development preview; it is not a deployed website or an APK/AAB release.

## 1. Prerequisites and one-time setup

Use the Node version expected by this project:

```sh
source "$HOME/.nvm/nvm.sh"
nvm use 22.23.1
node --version
```

Expected Node version: `v22.23.1`.

From the repository root, install project dependencies when setting up the checkout for the first time, or after its lockfile/dependencies change:

```sh
cd /home/kali/gpt-workspace/bd-admission-app
pnpm install
```

Expo tunnel mode needs the ngrok helper. It is installed globally for the selected Node 22 environment, not as a dependency in this repository. If Expo reports that `@expo/ngrok` is missing, install it once:

```sh
npm install --global '@expo/ngrok@^4.1.0'
```

Do not upgrade Expo/React Native dependencies to address an Expo Go SDK mismatch; use a compatible Expo Go build or a dedicated development build instead.

## 2. Start the preview

In a terminal, run:

```sh
source "$HOME/.nvm/nvm.sh"
nvm use 22.23.1
cd /home/kali/gpt-workspace/bd-admission-app
pnpm exec expo start --host tunnel --port 8081
```

Keep this terminal/session open while previewing. Wait for the terminal to report that the tunnel is connected/ready and that Expo is waiting on port 8081. The CLI displays a QR code and a session-specific Expo URL.

Confirm Metro is running from another terminal on the same host:

```sh
curl -fsS http://localhost:8081/status
```

Expected response:

```text
packager-status:running
```

The URL generated by tunnel mode can change every time the server restarts. Use the current URL/QR shown by the running Expo session rather than saving an old tunnel URL.

## 3. Open BD Admission in Expo Go

- Make sure Expo Go is compatible with this project's **Expo SDK 57**.
- If Expo Go is on another device, scan the QR code shown by the running Expo terminal.
- If the server and Expo Go are on the same Android phone (for example, Kali/NetHunter Rootless and Expo Go on the phone), the phone cannot scan a QR code displayed on its own screen. Copy the current `exp://…exp.direct` tunnel URL from the terminal and open Expo Go's URL/manual-entry option to paste it. The exact menu label can vary by Expo Go version.
- Keep the server terminal running while using the app. The preview stops responding after the Metro process exits or the host loses connectivity.

If Expo Go reports that the project is incompatible, install an Android Expo Go version compatible with SDK 57 from [expo.dev/go](https://expo.dev/go), or use a compatible development build. Do not change package versions just to suppress this warning.

## 4. Continuous use during a work session

Start the server once and leave it running while you inspect the app. For code changes, Expo's Fast Refresh normally updates the open preview automatically. If the screen needs a manual reload, focus the Expo terminal and press `r`.

To reconnect after closing Expo Go or losing the connection:

1. Confirm the original Expo server terminal is still running.
2. Check `curl -fsS http://localhost:8081/status` from the host.
3. Reopen the current project URL in Expo Go. If the server was restarted, use the new URL/QR generated by that session.

If Metro becomes stuck, stop it with `Ctrl+C` and start it again using the command in section 2. If the port is already occupied, find and stop the previous Expo session before restarting; do not start multiple Metro servers for the same project/port. Use `--clear` only when a cache reset is needed:

```sh
pnpm exec expo start --host tunnel --port 8081 --clear
```

## 5. Stop the server

Return to the terminal where Expo is running and press `Ctrl+C`. Wait for the process to exit, then verify the local endpoint is no longer available:

```sh
curl -fsS --max-time 2 http://localhost:8081/status
```

After a successful stop, this check should fail to connect. This stops the app preview only; it does not shut down NetHunter, Android, or Desktop Commander.

## 6. Troubleshooting

- **Tunnel helper missing:** install `@expo/ngrok` globally with the command in section 1, then start Expo again.
- **Tunnel is not ready:** check connectivity, wait for the CLI's connected/ready message, and restart Expo if necessary.
- **Expo Go says incompatible:** use an Expo Go build compatible with SDK 57; do not perform an unrelated SDK upgrade.
- **Port 8081 is occupied:** stop the older Expo session first. If you deliberately select another port, use the URL and port shown by that new session for the whole preview session.
- **No usable QR scan on the same phone:** paste the current tunnel URL into Expo Go rather than trying to scan the phone's own screen.

This workflow verifies a live JavaScript development preview, not a production release. It does not build, install, or validate an APK/AAB, and it does not replace physical-device release QA.
