# Current state

Last updated: 2026-10-28 (full-application pass, resumed from a previous session).

## What exists and is wired end to end
- **Database**: `DbProvider` (src/db/provider.tsx) opens SQLite, enables WAL, runs versioned migrations, ensures the profile row, closes stale Flash sessions, finalizes an exam that expired while the app was closed, then syncs bundled question packs. Loading and error (with retry) states are rendered by app/_layout.tsx. A bad pack only produces a warning; a DB/migration failure shows a retry screen and deletes nothing.
- **Repositories** (src/repositories): content (catalogue, eligibility, question loading, rule resolution), sessions (Flash/exam persistence, exactly-once exam finalization, history), userData (profile, bookmarks, activity summary).
- **Screens** (app/): Home, Varsity (institutions), Institution detail (papers), Paper detail (rule notice, Flash/Exam/Browse), Medical (papers), Question browser, Flash setup/play, Standard Exam setup/play, Result (Flash and Exam, with exam answer review), Profile (name, language, default timer, target category, real progress, imported packs), Bookmarks, History, Engineering (clearly marked Coming Soon).
- **Flash Question**: one question at a time, 30 s default and configurable (5-600 s) timer, wall-clock deadlines refreshed on app foreground, no repeats until the pool is exhausted then reshuffle, answer/feedback/next/skip/finish, tap-vs-timeout race guarded, unlimited continuation, results with counts/accuracy/score/advice, persisted history.
- **Standard Exam (current limitation)**: starts only with at least 100 eligible questions (picks exactly 100); explains the shortfall otherwise; 60-minute DB-stored deadline, grid navigation of all 100 positions, revise/clear answers, confirm-before-submit, timeout auto-submit, exactly-once finalization, resume and result review. The 100-question/60-minute values are currently fixed in the app and do **not** represent every university's pattern. Before real question packs are considered release-ready, replace these globals with a verified per-paper/year/session/unit pattern (and section rules where officially required). Some exams may have 80 or 60 questions instead; never pad or truncate them to fit the current MVP configuration.
- **Scoring**: verified / illustrative / unconfigured rules are preserved and displayed on setup, result and paper screens; unverified rules are never called official; questions without a verified answer are excluded from practice pools and never scored.
- **Import**: validator + transactional idempotent importer + startup sync of bundled packs (src/content/bundledPacks.ts is generated by `pnpm packs:index`). No real question packs have been supplied, so the app correctly shows empty states.
- **Localization**: Bangla/English dictionary (all keys have both languages and matching placeholders, enforced by a test); language persisted in AsyncStorage and mirrored in the profile table; Bangla digits for numbers.
